# Hearth for iPhone and iPad

The native SwiftUI client. It ships alongside the web app and talks to the same backend. Read [`docs/hearth-native-ios-plan-v2.md`](../docs/hearth-native-ios-plan-v2.md) before changing anything here: it sets which features are native, which stay on the web, and the API contract rules.

## Open and run

1. Open `apple/Hearth.xcodeproj` in Xcode (27+). Swift packages (ClerkKit) resolve on first open.
2. Copy `Config/Local.xcconfig.example` to `Config/Local.xcconfig` and set the Clerk publishable key and web origin. They must belong to the same Clerk instance. For local work, use the `pk_test_` key from `.env.local` with `http://localhost:3000` and `npm run dev`.
3. Run the **Hearth** scheme on any iPhone or iPad simulator.

No Clerk key yet? Add `-HearthDemo` under *Scheme → Run → Arguments* (Debug builds only) to run the signed-in app against canned data with no network. Add `-HearthTab story|log|plan|explore|settings` to open on a given tab.

## Layout

| Folder | What lives there |
|---|---|
| `Hearth/App` | Entry point, configuration, app-wide services, debug demo mode |
| `Hearth/Navigation` | `AppShell`: tab bar on iPhone, sidebar on iPad |
| `Hearth/DesignSystem` | Tokens transcribed from `src/app/globals.css`, fonts, motion, shared components |
| `Hearth/Networking` | `APIClient` (Clerk bearer token → `/api/*`), models, `FamilyStore` |
| `Hearth/Offline` | `Outbox`: Logger entries queued on disk with the web outbox's retry rules |
| `Hearth/Features` | Native screens: Home, Story, Log, Settings |
| `Hearth/Web` | `WebFeatureView`, which hosts web-homed features inside native chrome |
| `HearthTests` | Swift Testing suites. `Fixtures/` are the API contract |

## Rules

- **Project file.** `project.yml` is the source; `Hearth.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) and committed. Source folders are *synced*, so adding a Swift file needs no regeneration. Run `xcodegen` in `apple/` only after editing `project.yml`.
- **Tokens move together.** A colour, radius or motion change in `globals.css` lands in `DesignSystem/` in the same PR.
- **Icons.** Native screens use SF Symbols, the platform's equivalent of the web's Phosphor set. Don't add custom or decorative icon art (design rule 11).
- **API changes are additive.** If a PR changes a route the app reads, update `HearthTests/Fixtures/` and the Swift model in the same PR.
- **Concurrency.** Swift 6 with MainActor default isolation. Mark pure value types and token enums `nonisolated` when non-UI code (e.g. `Layout`) needs them.

## Test

```bash
apple/scripts/test.sh
```

Runs the unit tests on an iPhone and an iPad simulator. CI has no macOS runner yet, so run this before opening a PR that touches `apple/`.
