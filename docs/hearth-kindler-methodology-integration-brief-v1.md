# Kindler Workstream Integration Brief — Methodology Overlay Bundle

> **Workstream:** Kindler in Claude Code
> **Authority:** `hearth-methodology-overlay-bundle-v1.md` (canonical spec)
> **Paired brief:** `hearth-runtime-methodology-integration-brief-v1.md` (consumption side)
> **Priority:** HIGH — paired with the Kindler v6 Pedagogy Lens Bundle build

---

## What Kindler Is Absorbing

The Methodology Overlay Bundle is a content-time-generated artefact set keyed by `practiceKey` and stored on the module document. It runs in parallel with the existing Pedagogy Lens Bundle generation in the Kindler's async save job.

This brief covers:

1. Schema additions Kindler writes
2. Affordance inference logic Kindler runs at save time
3. Overlay generation prompt structure
4. Validation pipeline integration
5. Status flag semantics
6. Files to update with version bumps
7. Acceptance criteria

The runtime consumption side (Logger, Module Experience, Constellation) is covered in the paired runtime brief.

The existing `practice` Sanity type needs a `practiceVocabulary` field (used in prompt interpolation):


## 2. Affordance Inference Logic

When the Kindler saves a parent-built module, after universal schema validation but before the async generation job kicks off, run the affordance inference pass.

### 2.1 Inference rules (v1 heuristics)

Each rule contributes affordances to a candidate set. After all rules run, deduplicate, then cap at 6, prioritising practices anchored in the family's selected pedagogy.

| Module characteristic | Practices contributed |
|---|---|
| Pathway type = `inquiry` | `narration`, `documentation`, `extended-projects` |
| Pathway type = `material` | `hands-on`, `short-lessons` |
| Pathway type = `process` | `hands-on`, `documentation`, `rhythm` |
| Pathway type = `retrospective` | `documentation`, `free-play` |
| Capability threads include scientific/observation threads | `nature-journaling`, `narration` |
| Capability threads include literary/oral language threads | `narration`, `living-books`, `memory-work`, `copywork` |
| Capability threads include movement/physical threads | `movement`, `hands-on` |
| Capability threads include creative/arts threads | `hands-on`, `documentation` |
| Capability threads include math/quantitative threads | `hands-on`, `short-lessons` |
| Module duration ≤ 25 minutes | + `short-lessons` |
| Module duration > 90 minutes or multi-session | + `extended-projects` |
| Activity descriptions contain "outdoor", "garden", "nature" (case-insensitive) | + `nature-journaling`, `free-play` |
| Activity descriptions contain "story", "read", "tell" | + `living-books`, `narration` |
| Activity descriptions contain "memorise", "recite", "verse" | + `memory-work` |
| Activity descriptions contain "copy", "transcribe", "handwrite" | + `copywork` |

### 2.2 Curated pack handling

For curated packs, the `methodologyAffordances` field is set by the content team during pack authoring. The Kindler reads but does not regenerate it. If the field is empty on a curated module, fall through to inference as a safety net but log a warning to the Content QA queue.

### 2.3 Refinement path

These heuristics are v1. After observing real outputs from parent-built modules, expect to refine. The inference rule set should live in a single file (`kindler/methodologyAffordanceInference.ts`) so it can be updated without touching the rest of the Kindler.

## 3. Overlay Generation Prompt Structure

The Kindler runs one Haiku call per `(moduleId, practiceKey)` in the generation set.

### 3.1 Prompt template

```
SYSTEM:
You generate per-practice methodology overlays for a homeschool platform's
modules. The output is consumed by parents whose family has selected this
practice as part of their teaching approach.

Each overlay has up to four fields:
- loggerPromptHint: 12-20 words. A single prompt that helps a parent capture
  evidence of this practice happening during the activity.
- prepHint: 35-60 words. Practical guidance on how this practice plays out
  in this specific module.
- observationCue: 12-20 words. What this practice trains a parent to notice.
- evidenceTagBias: list of up to 4 capability thread keys (from the supplied
  list) that this practice tends to surface in this module.

CRITICAL: Honest density. If this practice does not genuinely fit this
module, return null for the field(s) where you have no substantive content.
Empty output for a field is correct and preferred over generic padding.

Banned phrases: [list interpolated from singleton]

Voice: warm, specific, grounded. Use the practice's vocabulary naturally
(narration uses "tell back" / "in their own words"; copywork uses "passage"
/ "transcribe"). Do not explain what the practice is — assume the parent
knows.

Output format: JSON only, no preamble or markdown fences.

USER:
Practice: {practiceKey}
Practice vocabulary: {practiceVocabulary[]}
Module title: {module.title}
Module summary: {module.summary}
Module activity descriptions:
{module.activities[].description}
Module capability threads: {module.threads[]}
Module pathway type: {module.pathway}
Module duration: {module.duration}

Available capability thread keys for evidenceTagBias:
{module.threads[]}

Retrieved corpus chunks (for grounding):
{retrieved chunks from RAG, filtered by practice-relevance tags,
 each tagged with corpusChunkId for provenance}

Generate the overlay as JSON conforming to:
{
  "loggerPromptHint": string | null,
  "prepHint": string | null,
  "observationCue": string | null,
  "evidenceTagBias": string[],
  "corpusChunkIds": string[]
}

If a field has no substantive content, return null. Do not pad.
```

### 3.2 Retrieval step

Before the Haiku call, run the RAG retrieval:

1. Embed the module's title + summary + threads using `text-embedding-3-small` at 1536 dimensions.
2. Query `pgvector` for top-K (K=8) similar chunks from the corpus.
3. Filter chunks to those whose source pedagogy is in the practice's anchor pedagogies (per Section 9 of the canonical spec).
4. Filter further by `themes:` tags matching the practice's keyword set (defined per practice in Sanity).
5. Pass top 4 surviving chunks into the prompt as grounding.

For the `documentation` practice (no corpus anchor), skip RAG and use a Sanity-stored practice template instead. The Haiku call still runs but with template guidance rather than corpus grounding.

## 4. Validation Pipeline Integration

Reuse the existing pedagogy bundle validation pipeline with three additions:

1. **Banned-phrase check** applies to `loggerPromptHint`, `prepHint`, `observationCue` (string fields only).
2. **Cross-field similarity check** applies within an overlay — `loggerPromptHint`, `prepHint`, `observationCue` must not paraphrase each other (cosine similarity threshold same as pedagogy bundle).
3. **Length check** enforces:
   - `loggerPromptHint`: 12–20 words
   - `prepHint`: 35–60 words
   - `observationCue`: 12–20 words
   - `evidenceTagBias`: 0–4 items, each must be a valid thread key from `module.threads`

On rejection, re-prompt up to twice. On third rejection, omit the field. Three field omissions across an Overlay causes the entire Overlay to be skipped for that practice on that module.

For curated packs only: any field omission triggers `methodologyStatus: 'partial_needs_review'`. Module is still publishable; flagged for content-team review in the Content QA Pipeline tool.

For parent-built: partial overlays are valid and shipped silently. No status flag exposed to the parent.

## 5. Save Flow Extension

The existing async overlay job (currently generating only Pedagogy Lens Bundles) is extended to also generate Methodology Overlays. Both run in parallel within the same job.

```
[existing] Module saved → lensStatus: pending
[NEW]      Affordance inference runs → methodologyAffordances populated
[NEW]      Module saved → methodologyStatus: pending
           ↓
Async job dispatched:
    ├─ Pedagogy Lens Bundle generation (unchanged from existing spec)
    └─ Methodology Overlay generation (new)
        For each practiceKey in (familyPractices ∩ moduleAffordances):
            ├─ RAG retrieval (filtered to practice's anchor pedagogies + theme tags)
            ├─ Haiku call with prompt above
            ├─ Validation (banned-phrase, cross-field similarity, length)
            ├─ Re-prompt on reject (up to 2 retries)
            └─ Write or skip per validation outcome
        ↓
        Set methodologyStatus = 'ready' if all overlays completed
                              = 'partial_needs_review' if any field omissions (curated only)
    ↓
Job complete. Module surfaces both bundles and overlays on next read.
```

The 5-minute rule is preserved: parent navigates away after save, entire async job completes in the background. Total job duration target: under 30 seconds for parent-built modules.

## 7. Acceptance Criteria

A Kindler implementation of this brief is complete when:

1. A parent saves a module via the Module Builder. Within 30 seconds of save, the module document in Sanity has `methodologyAffordances` populated, `methodologyStatus` set to `ready` or `partial_needs_review`, and `methodologyOverlays` populated for each practice in `(familyPractices ∩ moduleAffordances)` with at least one substantive field per overlay where the practice genuinely fits the module.

2. A curated pack module with `methodologyAffordances` set by the content team produces overlays for all 12 practices ∩ affordances, with field-level omissions triggering `partial_needs_review` flag.

3. A non-affordant practice on a module produces a fully-skipped overlay (no `methodologyOverlay` document for that practice in the array).

4. The validation pipeline rejects banned-phrase outputs, cross-paraphrasing fields, and length violations, with up-to-2 re-prompts and field omission on third failure.

5. The corpus retrieval is filtered by practice-relevance tags and returns chunks anchored in the pedagogies historically associated with the practice.

6. The 5-minute rule is preserved end-to-end: parent never waits on overlay generation.

7. The save flow does not regress any existing pedagogy bundle behaviour. Both paths run in parallel within the same async job and complete independently.
